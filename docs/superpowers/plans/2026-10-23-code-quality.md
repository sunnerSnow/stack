# 優先改善計畫

沿用現有 Next.js、Zod、Vitest 與 PGlite，依使用者接受的審查順序直接修正；在目前工作目錄交付可檢閱的修改，不提交或部署。

1. 轉強篩選：以 PGlite 回歸測試確認缺少五天前行情／座標不算轉強；五日成交均額須有完整資料。
2. 資產搜尋：區分失敗與無結果、結束載入、提供重試；忽略已取消請求。交易與快照表單都顯示失敗狀態。增加可執行的回歸測試。
3. 環境設定：逐項檢查 URL、金鑰、資料庫，只有全部空白才可進入本機模式；測試完整、部分與正式環境設定。
4. 日期驗證：市場 API 共用既有 isoDate 規則，無效日期回傳 400；測試閏年、無效日期及省略日期。
5. 市場完整性：保留法人缺值，期間資料不足不當成完整總額；同步修改排名、圖表與表格，測試缺值及真實零值。以實際交易日曆判斷期間，不能用更早的紀錄湊數；法人晚到時只更新衍生金額，保留歷史座標。

每項先執行失敗的回歸測試再修正。最後執行全部測試、lint、型別檢查與正式建置，記錄受環境限制的檢查。

精度邊界、CI、端對端測試與大型服務拆分為後續項目，避免與這批正確性修正混合。
